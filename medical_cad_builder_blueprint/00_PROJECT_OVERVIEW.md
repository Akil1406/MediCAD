# Medical Tool CAD Builder — Full-Stack Project Overview

## Technology Stack
- **Frontend:** React + TypeScript + Vite
- **Backend:** Python + FastAPI + Pydantic + SQLAlchemy
- **AI:** LangChain + LangGraph
- **CAD:** CadQuery with STEP/STL export
- **Database:** SQLite for MVP; PostgreSQL later
- **Future engineering:** FEA/CFD integrations

## Architecture

```text
React + TypeScript Frontend
        |
        | REST / WebSocket
        v
Python FastAPI Backend
        |
   +----+--------------------+
   |                         |
   v                         v
LangChain + LangGraph   Deterministic Services
AI reasoning/workflow   CAD / Materials /
                        Validation / Simulation
   |                         |
   +------------+------------+
                v
       Database + File Storage
```

## Core Workflow

```text
User describes device
        ↓
React → FastAPI
        ↓
LangGraph extracts requirements
        ↓
Pydantic validates specification
        ↓
CAD template selected
        ↓
CadQuery generates model
        ↓
Geometry/design checks
        ↓
Material candidates
        ↓
React displays model/results
        ↓
User edits dimensions
        ↓
FastAPI regenerates CAD
        ↓
Human approval
        ↓
STEP / STL / JSON / report
```

## Critical Rule

The LLM is the reasoning/orchestration layer, **not** the CAD engine.

Use:

```text
LLM → validated structured parameters → deterministic Python/CadQuery
```

Never execute arbitrary Python/CAD code generated by the LLM.

React must never directly access the database, filesystem, CAD engine, simulation software, or LLM credentials. Everything goes through FastAPI.

> This is an engineering prototyping platform and must not claim clinical safety, biocompatibility, sterility, regulatory approval, or patient readiness.
